# Sprint 2026-07-25 — ML Workshop Competition

## Sprint goal

Deliver everything needed for the ML workshop final competition on **July 25, 2026**.

## Deliverables

1. **Add level `1-17`** — create the symbol-based level code, add it to `Constants.LEVELS`, set medal times, and verify playability. The level must be loadable by name for the AI training mode, but should **not** appear in the regular level-select menu (add a hidden flag or filter so procedural population skips it).
2. **Record distinct tiles touched by the player** — see implementation notes below.
3. **Check for breaking bugs** — verify the items flagged in [[project/active-backlog]]#phase-1--hackathon-prep-and-quick-bugfixes do not block the competition build.

## Definition of done

- [x] Level `1-17` is in `Constants.LEVELS` and can be loaded/completed from the AI training mode. *(user is reimplementing the layout, but entry exists and is functional)*
- [x] Level `1-17` does **not** appear in the regular level-select menu.
- [x] A player run on `1-17` reports a distinct-tiles-touched count > 0.
- [x] The count resets correctly on restart.
- [x] No regression in existing levels `1-1` through `1-16`.
- [x] No crash or soft-lock in the main paths (menu → level → finish → retry → next level).

## Implementation notes

### Distinct-tiles tracking

- Track which grid cell the player is in each physics frame.
- Use a `Dictionary` with `Vector2i` keys as a set.
- Expose `Player.get_distinct_tiles_touched_count()`.
- Reset the set on `Player.reset()`.
- Add the count to `PlayerAITrainingController.get_info()` so the Python side can read it without changing the observation space.

## Out of scope for this sprint

- Foundation cleanup (Phase 2).
- New art, music, or sound.
- Map editor, QR sharing, or workshop integration.
- Ghost race mode.
- Arcade mode (Phase 3; the competition sprint does not build or verify it).
- Adding levels beyond `1-17`.

## Notes

- The level should encourage crossing almost the entire map before finishing, per the competition rule.
- Distinct-tiles tracking should be lightweight and not break deterministic replay if possible.
